1. 3NF Normalization & Functional Dependencies

Every non-prime attribute depends on the key, the whole key and nothing but the key

3NF Verified

Campus, Asset & Request Core

BUILDING (BuildingID, BuildingCode, BuildingName, Floors)3NF
• FD1: BuildingID → BuildingCode, BuildingName, Floors
• Candidate keys: {BuildingID}, {BuildingCode}, {BuildingName}
ROOM (RoomID, BuildingID, RoomNo, FloorNo, RoomType)3NF
• FD1: RoomID → BuildingID, RoomNo, FloorNo, RoomType
• FD2: (BuildingID, RoomNo) → RoomID (alternate key)
ASSET (AssetID, RoomID, AssetTag, AssetName, InstalledOn)3NF
• FD1: AssetID → RoomID, AssetTag, AssetName, InstalledOn
• FD2: AssetTag → AssetID (alternate key)
TECHNICIAN (TechID, FullName, Phone, CategoryID, MaxActiveJobs, IsActive)3NF
• FD1: TechID → FullName, Phone, CategoryID, MaxActiveJobs, IsActive
MAINTENANCE_REQUEST (RequestID, RequestNo, RequesterID, RoomID, …)3NF
• FD1: RequestID → RequestNo, RequesterID, RoomID, AssetID, CategoryID, PriorityID, Description, CreatedAt, Status, ClosedAt, ClosureRemarks
• FD2: RequestNo → RequestID. Building is NOT stored: RoomID → BuildingID lives in ROOM.
STATUS_TRANSITION (FromStatus, ToStatus)3NF
• All-key relation: (FromStatus, ToStatus) → ∅. No non-prime attributes, so 3NF holds trivially.

Work, Material, Cost & Feedback

ASSIGNMENT (AssignmentID, RequestID, TechID, AssignedAt, CompletedAt, Status)3NF
• FD1: AssignmentID → RequestID, TechID, AssignedAt, CompletedAt, Status
• Reassignment keeps history as extra rows, not repeating groups.
WORK_LOG (LogID, AssignmentID, LogTime, WorkNotes, HoursSpent)3NF
• FD1: LogID → AssignmentID, LogTime, WorkNotes, HoursSpent
MATERIAL (MaterialID, MaterialName, Unit, UnitCost, StockQty, ReorderLevel)3NF
• FD1: MaterialID → MaterialName, Unit, UnitCost, StockQty, ReorderLevel
• FD2: MaterialName → MaterialID (alternate key)
MATERIAL_USAGE (UsageID, LogID, MaterialID, Quantity, UnitCost)3NF
• FD1: UsageID → LogID, MaterialID, Quantity, UnitCost
• UnitCost is a price snapshot at time of use, not determined by MaterialID alone, so no transitive dependency.
REQUEST_COST (CostID, RequestID, CostType, Amount, Remarks)3NF
• FD1: CostID → RequestID, CostType, Amount, Remarks
• Material cost is derived by query, never stored twice.
FEEDBACK (FeedbackID, RequestID, Rating, Comments, SubmittedAt)3NF
• FD1: FeedbackID → RequestID, Rating, Comments, SubmittedAt
• FD2: RequestID → FeedbackID (one feedback per request)
Remaining relations (Campus_User, Category, Priority, Status_History) are single-key tables with the same pattern: PK → all other attributes.

3. DDL Scripts, Integrity Constraints & Triggers

Five required business rules plus cross-table integrity, enforced by the database itself

Business Integrity
Rule 1

Unique Request Numbers

One business number per request, in a fixed format.

RequestNo VARCHAR(13) NOT NULL UNIQUE, CONSTRAINT chk_req_no_format CHECK (RequestNo LIKE 'REQ-____-____')
Rule 2

Closure Details Required

A request cannot be Closed without remarks and a closing time.

CONSTRAINT chk_closure_details CHECK (Status <> 'Closed' OR (ClosedAt IS NOT NULL AND ClosureRemarks IS NOT NULL AND CHAR_LENGTH(TRIM(ClosureRemarks)) > 0))
Rule 3

Non-Negative Materials & Costs

Amounts, prices and stock can never go below zero.

Amount DECIMAL(10,2) CHECK (Amount >= 0), Quantity INT CHECK (Quantity > 0), StockQty INT CHECK (StockQty >= 0) -- trg_usage_bi: Quantity > stock -> SIGNAL
Rule 4

Valid Status Transitions

Moves are checked against the Status_Transition table.

SELECT COUNT(*) INTO ok_move FROM Status_Transition WHERE FromStatus = OLD.Status AND ToStatus = NEW.Status; IF ok_move = 0 THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Invalid Status Transition';
Rule 5

Assignment Control

Technician must be active, under load limit; one active job per request.

IF tech_active = 0 THEN SIGNAL ...; IF tech_load >= tech_max THEN SIGNAL ...; IF req_active > 0 THEN SIGNAL ...; -- trg_req_bu: In Progress needs an -- Active assignment
Rule 6

Cross-Table Integrity

Asset must sit in the request room; feedback only after closure.

-- trg_req_bi IF asset_room <> NEW.RoomID THEN SIGNAL ...; -- trg_feedback_bi IF req_status <> 'Closed' THEN SIGNAL ...;
9 triggers in total: trg_req_bi, trg_req_ai, trg_req_bu, trg_req_au, trg_asg_bi, trg_asg_ai, trg_usage_bi, trg_usage_ai, trg_feedback_bi (see review2_schema_ddl.sql).
